## 🌟 主要功能

- 🎮 **账号管理**
  - 绑定/切换/删除营地ID
  - 多账号管理支持
  - 账号信息展示

- 📊 **数据查询**
  - 战绩查询(最近30场)
  - 战绩详情(双方十人评分/经济/出装/参团率/承伤/控制/补刀 + 本人五维评级与分路百分位)
  - 排位表现(段位/积分/胜率/分路/常用英雄/雷达图/分路五维/上分趋势)
  - 巅峰表现(巅峰赛五维/全分路数据/上分趋势)
  - 英雄战力查询
  - 常用英雄战力榜(当前赛季排位/巅峰场次+胜率/战力/称号)
  - 我的英雄(全部英雄的场次/胜率/战力/荣耀称号,生涯累计)
  - 英雄梯度榜(T0~T3 实时强度,支持段位/分路筛选)
  - 英雄攻略(出装建议/铭文推荐/核心装备胜率/英雄关系/技能)
  - 英雄皮肤查询
  - 皮肤墙(按价值倒序，支持 TOP N / 全部)
  - 皮肤上新(今日上线/即将上线/最近上线,可按群订阅推送)
  - 游戏概览(段位/场次/MVP等)

- 🏆 **排行榜**
  - 排位排名(按段位星数跨段排序，青铜~荣耀王者)
  - 巅峰排名(按巅峰分排序)
  - 支持本群排名与全部绑定用户总排名
  - 数据本地快照缓存 12 小时，可发送「刷新」强制更新

- 📢 **战绩推送**
  - 打完一局自动在群里 @你 推全场战绩详情图 + 巅峰分/段位变化与连胜
  - 开局提醒(模式/英雄/该英雄场次胜率)
  - 上下线提醒(下线时附带本次在线时长与战绩总结)
  - 只有战绩推送 @ 本人，开局与上下线是给群友看的播报，不 @
  - 按人订阅，两个开关互相独立，只轮询开启过的人

- 📅 **战绩报告**
  - 个人日报/周报/月报(场次胜率、英雄榜、每日趋势、活跃时段、段位与巅峰分变化)
  - 群日报/周报/月报(全群成员战绩排行榜 + 肝帝/胜率王/MVP 收割机等称号)
  - 都支持指令即查与定时推送，个人按人订阅、群报按群订阅(限群管理)
  - 没打过的区间不推送，读本地战绩归档，不额外刷营地接口
  - 战绩归档可一键导出成 CSV(`#导出战绩`)，拿去 Excel 自己拉透视表

## 📦 安装方法

1. 在 Yunzai-Bot 根目录下执行:
```bash
git clone https://gitcode.com/ccxhan/GloryOfKings-Plugin.git ./plugins/GloryOfKings-Plugin/
```

2. 安装依赖:
```bash
pnpm install
```

3. 重启 Bot 即可使用

## 🎯 使用指南

### 账号管理
- `#绑定营地 [ID]` - 绑定营地ID,可绑定多个
- `#切换营地 [序号]` - 切换使用的营地ID
- `#删除营地 [序号]` - 删除绑定的营地ID
- `#我的ID` - 查看已绑定的营地ID列表
- `#营地wx登录` - 扫码登录营地，自动保存登录态并绑定当前营地ID
- `#营地wx全局登录` - 扫码登录并将账号加入全局账号池（主人命令）

### 主人命令
- `#王者用户统计` - 查看当前绑定与使用情况
- `#王者设置共享账号候选[启用|关闭]` - 开关共享账号候选功能
- `#王者设置个人登录态兜底[启用|关闭]` - 开关个人登录态兜底功能
- `#共享营地账号 [营地ID]` - 将指定营地账号加入共享账号池
- `#取消共享营地账号 [营地ID]` - 将指定营地账号移出共享账号池
- `#清理失效营地账号` - 清理失效的营地账号

### 数据查询
- `#王者主页` - 查看游戏信息概览
- `#全部王者主页` / `#全部主页` - 查看已绑定全部营地ID的主页
- `#查询战绩 [序号]` - 查看最近战绩，带序号查看指定场次详细数据
- `#排位战绩 [序号]` / `#巅峰战绩 [序号]` - 只看对应模式的战绩
- `#排位表现 [营地ID]` - 查看当前赛季排位表现（段位/积分/胜率/分路/常用英雄/雷达图/分路五维/上分趋势）
- `#巅峰表现 [营地ID]` - 查看巅峰赛表现（五维/全分路数据/常用英雄/上分趋势）
- `#查战力 [英雄名]` - 查询指定英雄的战力排名
- `#常用英雄 [营地ID]` - 查询当前赛季常用英雄战力榜，合并排位赛/巅峰赛两组常用英雄，按战力取前 5（场次/胜率/战力/称号）
- `#我的英雄 [营地ID] [数量]` - 全部竞技模式的生涯累计英雄榜，按战力排序取前 10（可跟数量改，最多 30），展示定位/熟练度/荣耀称号/场次/胜率/战力
- `#英雄梯度 [段位] [分路]` - 查看实时英雄梯度榜（T0~T3 胜率/登场率/Ban率），段位可选 所有段位/巅峰赛1350+/顶端排位/赛事，分路可选 对抗路/中路/发育路/游走/打野
- `#英雄攻略 [英雄名]` - 出装建议（两套，含官方 Tips）+ **铭文推荐**（3 套，带真实胜率/出场率）+ **核心装备**（3 件，带胜率/出场率）+ 英雄关系（最佳搭档/压制/被压制，含官方说明）+ 全部技能（冷却/消耗/描述），别名 `#出装` `#克制` `#铭文`
- `#查皮肤 [英雄名]` - 查询指定英雄的皮肤
- `#皮肤上新` - 今日上线 / 即将上线 / 最近上线的皮肤（封面图、品质、获取方式），别名 `#新皮肤` `#皮肤日历`
- `#皮肤墙 [营地ID] [数量]` - 按皮肤价值倒序展示前 N 张（默认 50，皮肤多时自动分页合并转发）
- `#全部皮肤 [营地ID]` - 展示账号拥有的全部皮肤

> `#英雄攻略` 的出装/英雄关系/技能来自**王者荣耀官网资料库**，`#皮肤上新` 也是官网数据 ——
> 这部分**一次营地请求都不发**，没绑营地ID、没有登录态也能用。
> **铭文推荐与核心装备的胜率/出场率来自营地官方接口**，属于增强项：拿不到（没登录态、频控）就自动跳过这两块，不影响出图。
> 官网与营地都是版本级更新，解析结果都在内存里缓存（攻略 6 小时、皮肤表 1 小时）。

#### 艾特查询

查询类指令都支持 `@某人` 查对方的数据，如 `@张三 #全部王者主页`、`@张三 #排位表现`，前置后置都行。

> 从 QQ 的 @ 候选列表里点选出来的是真 at 消息段；手打或粘贴出来的「@昵称」只是一段纯文本，
> 这种情况会按昵称/群名片去群成员列表里反查，认不出来会提示你重新点选。
> 账号管理类指令（绑定/切换/删除/wx登录）只有主人能艾特别人代为操作。

### 排行榜
统计**已绑定营地ID的用户**，取各自主页的排位段位星数与巅峰分生成榜单。

- `#排位排名 [刷新]` - 本群成员的排位排名（按段位+星数排序，跨段单调：荣耀王者 > 星耀 > 钻石 > ...）
- `#巅峰排名 [刷新]` - 本群成员的巅峰分排名（无巅峰分的账号不上榜）
- `#排位总排名 [刷新]` - 全部绑定用户的排位排名
- `#巅峰总排名 [刷新]` - 全部绑定用户的巅峰分排名

> 数据写入 `data/RankSnapshot.json` 快照，默认 12 小时内复用；带上 `刷新` 后缀可强制重新采集。
> 采集受营地接口频控限制，只能串行拉取（约 0.8 秒/账号），账号多时请耐心等待。
> 隐藏了营地主页的账号无法统计，不会出现在榜单里。

#### 自定义展示人数与缓存时长

以下几项没做成配置项，直接改源码里的常量即可，改完重启 Bot 生效。

| 想改什么 | 文件 | 常量 | 默认值 |
| --- | --- | --- | --- |
| 本群榜展示人数 | `apps/rankList.js` | `MAX_ROWS_GROUP` | `10` |
| 总榜展示人数 | `apps/rankList.js` | `MAX_ROWS_GLOBAL` | `30` |
| 快照有效期 | `utils/rankStore.js` | `SNAPSHOT_TTL` | `12 * 60 * 60 * 1000`（12 小时） |
| 每个账号的拉取间隔 | `utils/rankStore.js` | `REQUEST_INTERVAL` | `600`（毫秒） |

> 榜单是单列排布，前 3 名为大卡片、第 4 名起为普通行，人数调大后图片会明显变高。
> 超过 30 人时宽高比会超过 1:2，QQ 可能把图折叠成一条，需要点开才看得全。
> `REQUEST_INTERVAL` 调太小容易触发营地的 `-30107 操作频繁`，不建议低于 500 毫秒。

### 战绩推送 / 上下线提醒

**按人订阅**，只有开启过的人会被轮询。两个开关互相独立，各自订阅、各自关闭。

- `#开启战绩推送` / `#关闭战绩推送` - 打完一局在群里 @你 推战绩，开局也提醒一次
- `#开启上下线提醒` / `#关闭上下线提醒` - 上线和下线时在群里播报（不 @ 你），下线时附带本次战绩总结
- `#战绩推送状态` - 查看两个开关的状态与检查间隔
- `#清空王者战绩推送` - 清空全部订阅（主人命令）

都需要**在群里**发送，提醒会发到你开启时所在的那个群。

战绩推送发的是和 `#查询战绩 N` 同一张全场详情图（双方 10 人的英雄/出装/KDA/评分/评价、每人的参团率/承伤/控制时长/补刀与「全场最高」★标记、经济对比、防御塔与暴君主宰统计，以及查询者本人的五维评级 S/A/B/C 和营地算好的分路百分位），
文字部分只补图上没有的巅峰分变化与连胜：

```
@你 打完一局 · 巅峰赛
💧 失败 · 敖隐
📉 巅峰分 1807 → 1794 (-13)
🧊 当前 2 连败
[全场战绩详情图]
```

**只有「比赛结束推战绩」会 @ 你**，那是给你自己看的。上线、下线、进入比赛这三条是给群友看的热闹，
**不 @ 任何人**，但文案里带了游戏昵称，群里照样认得出是谁：

```
我就只会补兵 · 进入了巅峰赛
🎮 敖隐（478 场 · 胜率 49.79%）

🟢 我就只会补兵 · 王者已上线 · 已进游戏

⚫ 我就只会补兵 · 王者已下线 · 本次在线 2小时30分
🎮 打了 4 局 · 1胜3负
📉 巅峰分 1847 → 1831 (-16)
```

巅峰赛场次报巅峰分变化，排位场次报段位星数变化。

> **详情图要额外拉一次 battledetail 并走 puppeteer 渲染**（实测约 1.3 秒 / 280KB），
> 所以只给最新那一局出图：一轮补推多局属异常情况（重启 / 频控 / cron 被调长），
> 不该在异常时把成本放大到 N 倍，补推的旧局仍以文字列出。
> **出图失败（接口频控、渲染异常）会自动回退成纯文字 + 英雄头像**，不会把整条推送吞掉。
>
> **上下线提醒会多占一次接口请求**：战绩走战绩列表接口，在线状态走主页接口，是两个不同的端点。
> 只开战绩推送的人不受影响，两个都开的人每轮两次。
>
> 上下线只在「离线 ↔ 在线」跨越时提醒。营地的在线状态有三态（离线 / 在线 / 游戏中），
> 玩家在营地和游戏之间来回切会让状态在「在线」和「游戏中」之间跳，**这种抖动不会提醒**，
> 否则一晚上能刷几十条。「进了游戏」这件事由开局提醒负责（判据是真的进了对局，不是打开了客户端）。
>
> 开局提醒和战绩推送凑在同一轮时会合并成一条消息发（连着打排位时上一局结算与下一局开局
> 几乎总在同一轮被读到），不会一轮刷两条。
>
> 轮询间隔在 `#王者设置` 里改（配置项「推送检查间隔」，默认 2 分钟）。每个订阅要串行拉接口、
> 间隔 0.8 秒，**间隔设太短会触发营地频控 `-30107`，不建议低于 2 分钟**。
> 上一轮没跑完时下一轮会自动跳过并打 warn 日志。
>
> 隐藏了战绩/主页的账号推不了；开启订阅后 `#切换营地` 会自动跟随新账号并重置游标（不会把新号的历史战绩补推一遍）。
> 关掉配置项里的「推送总开关」则全局停止推送，**改完需重启 Bot 生效**（cron 在插件加载时注册）。

### 战绩报告（日报 / 周报 / 月报）

把一段时间的战绩汇成一张总结图。**数据读本地战绩归档**（`data/BattleArchive.json`），
正常不额外请求营地接口，所以查报告很快、也不吃频控。

#### 个人报告

- `#王者日报 [序号/营地ID]` - 今天 00:00 起的战绩总结
- `#王者周报 [序号/营地ID]` - 本周（周一 00:00 起）的战绩总结
- `#王者月报 [序号/营地ID]` - 本月（1 号 00:00 起）的战绩总结
- `#开启日报推送` / `#开启周报推送` / `#开启月报推送` - 到点自动在本群发（需**在群里**发送）
- `#关闭日报推送` / `#关闭周报推送` / `#关闭月报推送` - 取消对应推送

也支持 `@某人 #王者周报` 查别人的（别名 `#战绩日报` / `#战绩周报` / `#战绩月报`）。

图上有：总场次与胜负胜率、对局时长、段位星数与巅峰分变化、英雄使用榜（场次/胜率/均分）、
最长连胜、最佳一局、MVP 次数、模式分布、场均时长、最勤快的一天、24 小时活跃时段。
周报和月报多一张**每日战况**堆叠柱状图（胜/负分色）。

> **区间内没有对局就不推送**，不会发空图。
> 归档保留 35 天，刚好够「本月」；首次使用时归档可能还不全，图上会标明「数据覆盖自 X 月 X 日」。

#### 群报告

统计**本群成员 ∩ 已绑定营地ID**的账号（和 `#排位排名` 一个口径），每人只算他当前在用的那个营地ID。

- `#群日报` / `#群周报` / `#群月报` - 本群对应区间的战绩排行榜（不限权限，谁都能查）
- `#开启群日报推送` / `#开启群周报推送` / `#开启群月报推送` - **限群主 / 管理员 / 主人**
- `#关闭群日报推送` / `#关闭群周报推送` / `#关闭群月报推送` - 取消对应的群推送
- `#群报状态` - 查看本群三个开关与参与统计的账号数

图上有：全群总场次/胜负/胜率/人均场次/总时长、本区间称号（肝帝、胜场王、胜率王、
MVP 收割机、尽力局长、连胜之星）、成员排行榜（场次、胜负、胜率、MVP、时长、常用英雄、连胜徽标）、
全群热门英雄、全群活跃时段，周报月报还有每日战况图。

> **群报要逐个扫成员**：归档是否最新只能靠实拉第一页确认，所以每个参与统计的账号至少一次营地请求
> （全局队列 1.2 秒一发）。为控制耗时与频控，**最多统计 25 个账号**，按「归档里最新一场对局的时间」
> 倒序取，也就是最近在打的人优先。超出的人数会在图下方如实标出。
> 榜单最多列 15 人（改 `apps/groupReport.js` 的 `MAX_ROWS`），其余只报人数。
>
> 拿不到群成员列表时（官方机器人常见）会降级成「只统计在本群开过推送的成员」，图上也会标明。
> 群报订阅按群存在 `data/GroupReportPush.yaml`，和个人订阅互不影响；全群没人打的区间不推送。

#### 推送时间

七个 cron 都在 `#王者设置` 面板里改，**改完重启 Bot 生效**（cron 在插件加载时注册），留空 = 只保留指令、不自动推。

| 配置项 | 默认 |
| --- | --- |
| 战绩日报推送时间 | 每晚 23:47 |
| 战绩周报推送时间 | 周日 22:07 |
| 战绩月报推送时间 | 每月最后一晚 23:41 |
| 群日报推送时间 | 每晚 23:22 |
| 群周报推送时间 | 周日 21:34 |
| 群月报推送时间 | 每月最后一晚 23:18 |
| 皮肤上新检查时间 | 每天 12:26 |

> 月报的两个 cron 默认写成 `28-31 号每晚触发`：cron 表达不了「每月最后一天」（各月天数不同），
> 由插件在 28 号及以后只认真正的月末那天，不会连推四天。1~27 号触发照推（想每天看本月进度的可以自己改 cron）。

### 战绩导出

- `#导出战绩 [天数/营地ID]` - 把本地战绩归档导成 CSV 发出来（别名 `#战绩导出`）

不带参数导归档里的全部，跟数字导最近 N 天（如 `#导出战绩 7`），跟营地ID导指定账号。

> **零营地请求**：读的是 `data/BattleArchive.json`，所以能导多少完全取决于归档覆盖了多少天
> （最多 35 天，且开启战绩推送之前的场次没有），文案里会如实标出覆盖范围。
> 列有：对局时间、模式、结果、英雄、KDA、评分、MVP、时长、段位星数、巅峰分变化、评价。
> CSV 带 UTF-8 BOM，Excel 直接双击打开中文不乱码。文件落在 `data/export/`，只留最近 10 个。
> 发文件走三级回退（file 消息段 → 适配器 sendFile → base64），三条都失败时会把服务器路径告诉你。
